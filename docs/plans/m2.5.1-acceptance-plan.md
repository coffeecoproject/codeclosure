## 1. Purpose

This plan defines the independent executable exit assessment for the bounded
M2.5.1 compatibility and composition closure. It makes real Intake and the real
Intake-to-M2 Worker path mandatory evidence instead of an optional observation.

The assessment runner issues no historical M2.5 verdict, Intent Admission,
Goal/Workflow mutation, technical Acceptance, milestone verdict, or external-
effect authority. It may only report whether one exact source identity is ready
for independent review.

## 3. Acceptance question and bounded claim

The independent reviewer answers exactly:

> Does the exact reviewed source support the pinned real Codex App Server for
> bounded Answer-only and Intent-analysis Intake, and can trusted composition
> materialize one source-bound Goal whose ordinary Start uses real Codex for
> candidate-free `DISCOVERY`/`PLAN` over exact Runtime-owned read-only selected-
> source snapshots and Candidate-bound `IMPLEMENT`, modifies only an isolated
> Candidate, and reaches protected verification and technical Acceptance
> without giving the model source-checkout access, Intake, Profile-selection,
> Workflow, or completion authority?

An unconditional `PASS` proves only that bounded local claim. It does not prove:

- that the historical M2.5 assessment used real Intake;
- arbitrary-model or arbitrary-Codex-version compatibility;
- arbitrary-project verification completeness;
- M2.6 frontstage interaction or M2.7 Host behavior;
- automatic repair, Goal revision, queueing, or parallel workers;
- source-project promotion or mutation; or
- merge, release, deployment, or product completion.

## 5. Live evidence and privacy contract

The canonical M2.5.1 procedure requires live execution. A missing credential,
network path, model, pinned binary, or explicit authorization is `BLOCKED`; a
fixture cannot substitute for a mandatory live row.

Live evidence may retain only:

- exact source/tool/protocol/profile/policy/configuration identities and
  digests;
- command name, closed scenario ID, exit class, durations, counts, and closed
  reason codes;
- authority record IDs, versions, digests, dispositions, and safe bounded
  projections;
- Candidate/source identities, allowed-path diff metadata, check/evidence/
  acceptance identities, and result status; and
- raw artifacts whose owning schema and retention policy explicitly permit
  them.

It must not retain or print:

- authentication material or credential-file content;
- account identifiers or rate-limit values;
- user request or clarification text in diagnostic artifacts;
- assistant answer/proposal text outside the already governed bounded Intake
  records required by the tested product path;
- hidden reasoning, unrestricted transcripts, raw notifications, or raw
  exceptions; or
- source files unrelated to the declared Candidate change and protected check.

The harness should generate deterministic non-sensitive user inputs internally
and identify them by scenario digest in diagnostic evidence. Product authority
continues to retain exact safe Raw Request bytes under the accepted M2.5
retention contract; diagnostic output must not duplicate those bytes.
