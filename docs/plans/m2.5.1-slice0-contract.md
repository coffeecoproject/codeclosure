## 1. Claim and boundary

This record closes only M2.5.1 Slice 0. It freezes the additive identities,
protocol dispositions, real phase composition, bounded demonstration, and
future proof ownership that Slices 1 through 5 MUST implement and verify.

Slice 0 does not implement the corrected Intake Adapter, install the real
phase composition, run mandatory live evidence, or complete M2.5.1. It does
select the exact reviewed `0.146.1` lower-client binary/schema baseline and
closes legacy cross-version launch substitution before a process starts.
Historical M1, M2, and M2.5 records retain their original meaning. A future
producer name in the executable contract is a responsibility assignment, not

The JSON contract is the executable exact-value source for this record. The
Markdown contract states its authority and interpretation. A later change to a
frozen identity, disposition, baseline, or proof owner MUST update both forms,
run the Slice 0 contract test, and explain whether it is a compatible
correction or a new architectural decision.

## 3. Protocol projection contract

The lower Codex App Server Client remains the only raw JSON-RPC decoder. An
unsupported method, malformed envelope, correlation failure, or lower-client
limit closes at that boundary. Above it, `IntakeProtocolProjection` MUST be the
sole consumer of a successfully decoded `AppServerNotification`, MUST validate
the generic parameters for the exact method, and MUST emit exactly one member
of the closed eleven-kind `IntakeObservedEvent` union.

The executable contract assigns all 72 methods in the `0.146.1` generated
notification union and all 18 pinned `ThreadItem` types to exactly one
disposition. The Slice 0 test derives both source unions from the pinned client
surface and rejects omissions, duplicates, or extra assignments. Later
generated-protocol drift therefore fails closed until this contract is
explicitly revised.

The key rules are:

- `thread/started`, `turn/started`, and `turn/completed` provide only their
  exact lifecycle facts;
- `item/started` and `item/completed` are exhaustively discriminated by Item
  type;
- an empty progressive `agentMessage` start is valid, while completed and
  terminal message validation remains strict;
- rate-limit projection discards account values and emits only a content-free
  benign process fact;
- `remoteControl/status/changed` is benign only for the exact validated
  disabled state; connecting, connected, errored, malformed, and any other
  state is a protocol violation;
- command, file-change, tool, MCP, image, approval, Web Search, dynamic-tool,
  integration, and other effect-bearing activity is forbidden;
- warnings, deprecations, reroutes, compaction, unknown lifecycle, and known-
  method malformed parameters are protocol violations; and
- no `onCompactionEvent` or other side channel may bypass the Projection and
  classifier.

The fourteen frozen diagnostic categories expose only the owning layer and
closed failure class. They MUST NOT retain raw notification parameters,
request or response text, reasoning, account values, authentication material,
or raw exceptions. The Observer continues to enforce order, correlation,
budget, terminal binding, and response-contract validation; a normalized event
does not become Intake, Route, Admission, Goal, Start, or Acceptance authority.
