## 1. Claim and boundary

This record closes only the future implementation inputs for M2.6 Slice 0. It
freezes the accepted decisions, exact local identities, bounded grammar,
budgets, migration entry, startup/shutdown dispositions, and one future proof
owner for every mandatory acceptance row.

It does not implement an Interaction record, Store migration, Assistant
Adapter, Goal-summary query, persistent CLI, or acceptance runner. A planned
proof owner is a responsibility assignment, not evidence that its file exists,
runs, or passes. Slice 1 implementation MUST NOT begin until the bounded Slice
0 review closes this contract and the repository status documents agree.

The JSON contract is the executable exact-value source for this record. The
Markdown contract states its interpretation and boundary. A frozen semantic
change MUST update both forms and either remain a compatible pre-implementation
correction or receive a new accepted ADR when it changes durable architecture.

## 2. Accepted decision closure

ADR 0036 through ADR 0039 are accepted together as one bounded M2.6 decision
set. They preserve these owners:

- deterministic policy, not Assistant output, owns Route Decision and action
  authorization;
- M2.5 owns Intake Projection, Admission, Materialization, clarification, and
  ordinary Start;
- the public Runtime facade owns Goal reads and commands;
- Workflow Runtime and Acceptance Engine retain their existing mutation and
  technical-verdict authority; and
- the CLI owns only foreground input, presentation, and the bounded local task
  handle.

The exact initial `zh-CN` direct and confirmation grammar is defined only by
ADR 0036 and repeated as executable values in the JSON contract. Matching does
not normalize or rewrite the message. A governed Intake handoff retains the
complete original bytes including its direct-action prefix.

## 4. Record and persistence freeze

All M2.6 records start at schema version `1`, reject unknown fields, use named
RFC 8785 canonical projections, and persist authority plus audit atomically.
The executable contract freezes the closed Session/operation states, route and
action enums, response union, exact Profile/policy identities, and resource
budgets.

The first append-only migration is
`0037_frontstage_interaction.sql`. It must add Interaction authority without
rewriting or inferring M1, M2, M2.5, or M2.5.1 history. Strict reopen must
recompute every digest and relationship and reject partial, cross-session,
stale, multiply consumed, or unaudited authority.

Startup always creates a new Session after reconciliation; it does not attach
to an earlier Session or import old message/focus context. An authorized public
action may recover only by re-entering the same named capability with its
retained Command ID and canonical input. Assistant work is never recalled.

## 5. Bounded concurrency and shutdown freeze

One Session owns at most one execution-bearing task. Busy behavior, the exact
same-message `MATERIALIZE_ONLY` alternative, and confirmed active-Goal
cancellation follow ADR 0039. No delayed queue or project-wide execution slot
exists.

Graceful shutdown has a `10_000` millisecond deadline. The trusted
`interruptOwnedExecution` lifecycle capability may signal only the active
controller owned by the same in-process driver and Session task. It cannot
issue a command, cancel a Goal, select another Goal, or write Workflow state.
Exit `0` requires persisted settlement; deadline expiry returns exit `4` and
retains `CLOSING` for startup recovery; an untrusted shutdown state returns
exit `5`.

## 6. Proof ownership

The executable contract assigns every `M26-*` acceptance row to one exact
future producer. The acceptance runner must derive each test-owned observation
from the actual named TAP test emitted by that owner. File presence, source
markers, a Slice 0 contract pass, a planning probe, or a neighbouring stage
cannot satisfy a later acceptance row.

Runner-owned quality, regression, Live, and source-closure rows become observed
only after their full strict command or metadata receipt passes. The final
runner must reject skip, todo, waiver, unexpected not-applicable, source drift,
or missing owner evidence.

## 7. Slice 0 exit

Slice 0 may close only when:

1. all four ADRs and the ADR index agree on `Accepted`;
2. this Markdown and the JSON contract agree and the contract test passes;
3. the implementation and acceptance plans contain the same fixed values;
4. later capabilities are named directly in their owning milestones or M2.7
   plan and no competing temporary backlog remains;
5. README, `AGENTS.md`, `ARCHITECTURE.md`, domain status, plan indexes, and
   milestones consistently identify M2.6 Slice 0 as documentation/proof-
   contract work rather than feature implementation; and
6. the complete documentation check and unchanged M1/M2/M2.5/M2.5.1 baseline
   pass before Slice 1 begins.
