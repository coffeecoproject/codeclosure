## 3. Execution strategy

The five batches are serial review boundaries:

`B1 -> B2 -> B3 -> B4 -> B5 -> Slice 4`

Implementation, focused tests, and directly owned documentation MAY proceed
together inside one batch. A later batch MUST NOT activate behavior that
depends on an earlier batch until the earlier batch has met its exit gate and
has been committed.

Each batch uses this bounded loop:

1. confirm the batch diff starts from a clean working tree;
2. implement only the batch scope;
3. add or update the batch-owned deterministic proof at the same time;
4. run focused checks proportional to the affected authority boundary;
5. perform one findings-first bounded review;
6. fix material findings and perform one quick confirmation review;
7. commit the closed batch before starting the next one.

Repeated review without a new risk, changed diff, failed check, or unresolved
finding SHOULD NOT delay the next batch.

### B3 — Source currency and Driver Profile v3 dispatch

#### Scope

- Implement this batch through two ordered internal steps: first add a
  protocol-neutral phase-source/currency evaluator over the B2 observation

- Reuse and, only where required by the accepted checkpoints, additively extend

  introduce a second observer, projection, or authority representation.

  dispatch and after the Turn but before Worker result admission.
- Map exactly one applicable failure to `PROJECT_SOURCE_DRIFT`,
  `PROJECT_READ_SNAPSHOT_DRIFT`, or `PROJECT_READ_AUTHORITY_INVALID`.
- Terminalize the current Attempt as `INTEGRITY_VIOLATION`, discard the Worker
  result, and create no replacement Attempt on a failed currency check.

- Author and persist External Execution Intent/Record v2 with exactly one
  ProjectRead or Candidate source member.

  Worker Event, receipt, and observation schemas through their existing
  transitive bindings.

  FakeWorker fallback.

  make the Driver stop the current drive under that exact reason with no next

#### Boundary

- B3 may extend the B2 port surface only for the accepted pre-dispatch and

- Codex protocol types do not enter Runtime or the source/currency contract.
- Checks occur only at the ADR-defined checkpoints. They do not add continuous

- Adapter observations remain untrusted input and do not become Workflow,

- This batch uses deterministic external-Worker fixtures; it does not claim a
  real Live Codex path.

#### Exit gate

- Pre-dispatch and post-Turn drift branches close under their exact reason,

  failure tests pass for Intent/Record v2.
- A Driver-level test proves the retained `PLAN_SOURCE_NOT_CURRENT` result
