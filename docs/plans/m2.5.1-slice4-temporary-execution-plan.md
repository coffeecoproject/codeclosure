## 3. Owning layers and required structural correction

The trusted CLI composition owns assembly and root validation. Runtime owns
Projection, Admission, Materialization, Start, phase dispatch, source currency,
Workflow state, Evidence admission, and closeout requests. Candidate Manager
owns project-read and Candidate observations. The Codex adapters own protocol
projection and phase-local activity classification. Only the Acceptance Engine
may issue technical `ACCEPT`.

The focused evidence harness may invoke public Intake and Goal facades and read
strictly reopened authority. It MUST NOT write Store records directly, select a
Profile, synthesize a Workflow result, infer containment from model prose, or
turn its receipt into product authority.

One proofability gap must be corrected before the first linked Live operation:
the production Intake Assistant currently allocates its controlled operation
root lazily and keeps that root private. The complete composition therefore
cannot yet bind that exact root into the required pre-model pairwise-separation
check without relying on ambient temporary-directory behavior. The owning CLI
integration composition layer MUST expose a content-free prepared execution-
root descriptor before the first Assistant call and MUST bind that descriptor
to cleanup. The descriptor is trusted composition input only; it is not Domain,
Store, Audit, Evidence, Acceptance, or filesystem authority. The Intake Adapter
remains protocol-only and does not own the root. This is the smallest required
structural improvement; a caller-authored path claim or post-call directory
scan is not an acceptable workaround.

The correction MUST preserve ordinary M2.5 Intake behavior, fresh Thread/Turn
semantics, v3 Assistant identity, existing cleanup behavior, and the separation
between Intake Assistant and Goal-bound Worker capabilities. It MUST NOT expose
auth content, configuration bytes, request/response text, or Codex protocol
objects.
