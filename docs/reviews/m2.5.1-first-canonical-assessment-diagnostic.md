## Cause

The failure is owned by the Slice 5 assessment orchestration, not by the
product Runtime or the real Intake-to-Codex path. The canonical runner applied
one implicit 900000 ms timeout to every stage. The M2.5 regression intentionally
nests the complete quality gate, M1 regression, and current-source M2
regression before its M2.5-specific checks. In this run those prerequisite
stages had already demonstrated a combined duration greater than the enclosing
uniform timeout. The child process was therefore reported as a generic launch
failure even though its process exit status was zero.

Removing the timeout, skipping or splitting the mandatory regression, or
treating the interrupted result as a pass would violate fail-closed execution
and the frozen acceptance matrix. No Runtime, Worker, Evidence, or Acceptance
authority change is required.

## Corrective contract

The assessment library is the single owner of a closed, finite per-stage
command-timeout policy. The runner MUST consume that policy for every spawned
stage command, bind the selected budget and assessment-owned bounded-output
limit into the command digest, and classify Node `ETIMEDOUT` as
`COMMAND_TIMEOUT`. The same shared classifier MUST identify Node `ENOBUFS` as
`COMMAND_OUTPUT_LIMIT_EXCEEDED`, and stage-specific consumers MUST NOT replace
either process-level result with a second classification.
Nested regression stages receive bounded budgets sized for the child
procedures they deliberately compose; ordinary focused stages retain smaller
bounds. Either resource-limit failure still yields `FAIL` and blocks every
later proof owner.

The canonical procedure MUST be rerun from one later clean committed source.
Only a complete 68-row result with exact source closure can become input to the
independent M2.5.1 completion review.
