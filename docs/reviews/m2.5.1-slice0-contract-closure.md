## Review question

This review asks whether M2.5.1 may leave decision closure and begin Slice 1
without a later slice inventing or reinterpreting Intake identities, decoded
notification dispositions, exact Codex toolchain identity, real phase
ownership, candidate-free source authority, cleanup semantics, demonstration
success, or acceptance proof ownership.

The contract answers those design questions. It does not implement the
corrected Intake Adapter, project-read authority, real phase composition, or
mandatory live calls. It does not revise the historical M2.5 verdict. This
`PASS` permits Slice 1 only.

## Frozen contract findings

### Intake compatibility identities and projection

New Intake operations receive Assistant Profile schema 2 and Adapter version 2
identities plus one newly identified closed configuration and projection
policy. Version-1 response contracts, budget, Manifest, and Observation keep
their historical meaning and strict reopen/replay behavior.

The executable contract derives the selected generated surface and assigns all
72 successfully decoded notification methods and all 18 `ThreadItem` types to
one exact, disjoint disposition. It freezes eleven normalized event kinds and
fourteen metadata-only diagnostic categories. The lower Client alone owns raw
JSON-RPC admission; the Projection is the sole decoded-notification consumer
above it. An empty progressive message start and exact disabled remote-control
state are accepted narrowly, while completed/terminal content, unknown
activity, malformed parameters, forbidden effects, warnings, reroutes, and
compaction remain closed.

### Real execution composition and ADR 0043

The formal Profile selects real Codex for `DISCOVERY`, `PLAN`, and `IMPLEMENT`.
The first two phases require the exact ADR 0043 read-only selected-source
snapshot, forbid Candidate fields, and return only untrusted `PROPOSALS`.
`IMPLEMENT` requires the exact mutable Candidate lease, forbids candidate-free
snapshot fields, and returns only `COMPLETION_REQUEST`. Candidate authority
still begins only at `PLAN -> IMPLEMENT`; no fake component is a production
fallback.

The machine contract freezes the canonical phase set, Workflow execution
order, `ALL_SELECTED_ATTEMPTS`, exact canonical Domain capability grants,
response contracts, cwd/source-authority presence rules, and phase-local
activity dispositions. It also freezes Context version 5, external Profile
version 3, Intent/Record version 2, Codex directive version 3, Adapter
observation version 2, project-read schema names, source projections, cleanup
identity, and `PLAN_SOURCE_NOT_CURRENT` handling.

`ExternalExecutionObservationV1`, `WorkerRequestV2`, `WorkerEventV1`, and
`WorkerEventReceiptV1` remain unchanged only because their existing Intent or
Context Manifest/package/Profile causality transitively binds the new additive
source-authority member. The Slice 0 test inspects those current source fields;
no historical codec is silently widened.
