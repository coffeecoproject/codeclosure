## Findings

### Accepted decision set is closed

ADR 0036 through ADR 0039 are accepted together and preserve one owner for each
authority:

- deterministic policy owns Route Decision and authorization; Assistant output
  remains a proposal;
- M2.5 owns Intake Projection, Admission, clarification, Materialization, and
  ordinary Start;
- the public Runtime facade owns Goal reads and commands;
- Workflow Runtime and Acceptance Engine keep mutation and technical-verdict
  authority; and
- the CLI owns only foreground interaction, presentation, and its bounded local
  task handle.

The exact `zh-CN` direct and confirmation grammar is closed without normalizing
or reconstructing user content. A direct governed request hands the complete
original bytes to M2.5. Assistant-selected actions or Goal IDs cannot satisfy
authorization or focus. Exact M2.5 Question clarification receives no competing
Pending Action.

### Assistant, Goal query, and lifecycle inputs are exact

The new Frontstage Profile, Adapter, response contract, configuration, policy,
retention, and budget families have distinct version-1 identities. The
Assistant has an empty CodeClosure authority-capability set, a fresh bounded
operation, one strict proposal union, and fail-closed tool observation. It does
not reuse or relabel the Intake Adapter.

The Goal-summary contract has only `OPEN` and `ALL`, fixed page bounds and
ordering, a Runtime-authored watermark/cursor, exact project scope, and no
persisted read-side catalog authority. Focus may be written only from an exact
Runtime result, never from fuzzy text, a truncated label, or an Assistant hint.

Startup always reconciles retained work and creates a new Session. It imports
no old transcript or Focus and never recalls Assistant work. One Session may
own one execution-bearing task, with no queue or project-wide slot. Busy,
same-message materialize-only, active-Goal cancellation, same-Command-ID
recovery, the 10-second shutdown deadline, and exit `0`/`4`/`5` meanings are
fixed without adding CLI-owned Workflow state.

### Persistence and proof ownership are frozen without implementation claims

All planned Interaction records start at schema version 1, strict unknown-field
rejection, RFC 8785 projections, and atomic state/audit persistence. The first
append-only migration is `0037_frontstage_interaction.sql`; retained M1, M2,
M2.5, and M2.5.1 history is not rewritten.

The executable JSON contract assigns all 57 mandatory `M26-*` rows to exactly
one future test or runner producer. Those names are obligations, not evidence
that the files or M2.6 behavior already exist. The contract test rejects enum,
grammar, identity, budget, lifecycle, migration, or proof-owner drift.

### Deferred scope has one formal home

All nine former M2.6 decision items are closed in accepted ADRs, the contract,
or the reviewed README status-source migration. Later capabilities are named
directly in M2.7, M3, M4, or M5. The temporary deferred-boundary TODO is deleted
rather than retained as a competing backlog. No Runtime Host, detached
execution, scheduler, Fact Graph, rich operator UX, multi-agent system,
multi-user runtime, or promotion authority enters M2.6.
