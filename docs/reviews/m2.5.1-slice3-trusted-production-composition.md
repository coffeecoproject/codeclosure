# M2.5.1 Slice 3 Trusted Production Composition Review

- Review date: 2026-08-11
- Scope: M2.5.1 Slice 3 only
- Status: Implemented and deterministically validated
- Verdict: `PASS`; Slice 4 may begin after this reviewed batch is committed,
  but no mandatory Live path, M2.5.1 milestone completion, or M2.6 work is
  claimed

## Review question

This review asks whether Slice 3 closes the trusted production composition from
the exact M2.5.1 Policy/Profile and ordinary Start through candidate-free
`DISCOVERY`/`PLAN`, Candidate-bound `IMPLEMENT`, protected verification,
Evidence, Acceptance, closeout, cleanup, restart, and replay while preserving
the existing authority owners and providing exact deterministic proof owners.

It does not ask whether that composition has run through the pinned real Codex
binary. The deterministic full-chain test injects an explicit protocol fixture
through the trusted Adapter seam. Effective live containment, the mandatory
real user path, the canonical M2.5.1 assessment, milestone completion, and
M2.6 remain later work.

## Reviewed implementation boundary

Slice 3 was implemented through the five serial batches frozen in the
[temporary execution plan](../plans/m2.5.1-slice3-temporary-execution-plan.md):

- B1 installs and strictly resolves the exact formal Policy/Profile and binds
  Materialization plus ordinary Start without rebinding historical Goals;
- B2 creates the ProjectRead snapshot, Context v5, Attempt, cleanup authority,
  and crash reconciliation through their existing Runtime, Store, and local
  Workspace owners;
- B3 adds Runtime-owned source-currency checkpoints and Driver Profile v3
  dispatch with no FakeWorker fallback;
- B4 publishes the trusted graph only after activation and startup
  reconciliation and proves the deterministic Intake-to-closeout chain; and
- B5 reconciles the frozen deterministic proof owners, documentation, and
  independent Slice 3 verdict.

No batch adds a second Workflow writer, Candidate owner, Evidence issuer,
Acceptance authority, project scheduler, Host, Frontstage, automatic repair,
release, promotion, or deployment path. Fake Worker, Candidate Source, and
Verification components remain explicit test infrastructure and are not a
production fallback.

## Bounded review findings

The first B5 pass found two material proof-closure defects rather than a new
architecture defect:

1. several tests existed under filenames that no longer matched the exact
   proof-owner paths frozen by the Slice 0 contract; and
2. Candidate containment was covered below the composition boundary, but the
   trusted B4 production graph lacked a direct containment-failure scenario.

The correction preserves the frozen contract rather than rewriting it to fit
the implementation. The affected owner files now register their exact marker
as an executable proof argument, with shared scenarios and assertions held in
non-test proof modules where a case must be exercised by more than one owner
suite. The closure check rejects a marker found only in a comment. This avoids
copied assertions, parallel authority models, duplicate test discovery, and a
growing conditional dispatcher.

The new production-composition failure case causes an out-of-policy Candidate
change through the same fixture seam as the success chain. It proves exact
`CANDIDATE_CHANGE_OUTSIDE_ALLOWED_PATHS` closure, Candidate invalidation, no
Evidence, no Acceptance or closeout, balanced phase-resource cleanup, unchanged
source identity, and no Fake fallback. The production path itself was not
weakened to make the test pass.

No additional material finding remained after the correction review. The
changes do not require a new ADR because they implement accepted ADR 0043 and
ADR 0044 without changing an authority owner or durable architectural
decision.

closure case `M251-S3-01`, which reads that map and requires every implemented
Slice 3 owner to resolve to a portable repository-contained regular file, not
a symbolic link, with its exact marker participating in executable owner
registration rather than only a comment.

The resolved rows are:

| Boundary | Frozen rows |
| --- | --- |
| retained external compatibility | `M251-V06` |
| trusted Policy/Profile, Start, ProjectRead, dispatch, activity, and change containment | `M251-C01` through `M251-C11` |

| composition, verification, reopen, source mismatch, cleanup, crash, and concurrency failure closure | `M251-F04` through `M251-F11` |

This check does not turn a filename or marker into product authority. It only
prevents the accepted assessment contract from silently pointing at a
different or absent deterministic proof.

trusted graph, failure closure, frozen proof owners, and documentation are
ready to commit. Slice 4 may begin from that committed boundary. M2.5.1 remains
incomplete, and M2.6 must not begin.
