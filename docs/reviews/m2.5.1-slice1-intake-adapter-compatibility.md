## Review question

This review asks whether new Intake operations can select one deliberately
versioned Codex `0.146.1` Profile and Adapter that implement the frozen Slice 0
decoded-notification contract, while retained version-1 authority keeps its
historical meaning and every unknown, malformed, forbidden, or unbound event
still fails closed.

It does not ask whether the corrected Adapter works against the real model
service. Those mandatory Answer-only and Intent-analysis calls belong to Slice
2. It also does not compose candidate-free `DISCOVERY`/`PLAN`, Candidate-bound
`IMPLEMENT`, protected verification, Evidence, Acceptance, or closeout.

## Implemented boundary

New operations compile the version-2 Intake Profile, Adapter, configuration,
and protocol-projection identities frozen by Slice 0. The version-2 closed
feature set omits only the two deprecated Web Search keys identified by the
diagnostic; it does not weaken version, launch, capability, or effect checks.

Above the lower Client, `IntakeProtocolProjection` is the sole consumer of
successfully decoded notifications in the version-2 strategy. Its private
classifier exhaustively covers the pinned 72 notification methods, validates
all 18 `ThreadItem` variants and all 16 nested raw `ResponseItem` variants, and
emits only the frozen closed 11-event union. The version-2 Observer consumes
that union, not Codex protocol types. There is no version-2 compaction callback
or other decoded-notification side channel.

The first Slice 1 review found one disposition error in its own frozen table:
the outer `rawResponseItem/completed` method was treated as stream progress
after validating but discarding the inner type. Slice 0 contract v3 corrects
that table without changing an authority or Adapter identity. Raw assistant
messages and reasoning now remain content-free lifecycle observations; raw
collaboration, shell, function, tool-search, custom-tool, Web Search, image, and
output variants fail as forbidden effects; raw compaction and `other` fail as
protocol violations. Tests cover those failures both before and after a
provisional terminal and retain no raw payload.

The corrected handling is stage-aware:

- an empty progressive `agentMessage` start is accepted only as a start;
- a completed message and the selected terminal answer still require valid
  non-empty bounded content;
- disabled remote-control, rate-limit, thread-status, and thread-token
  projections are admitted only through their exact benign shapes; and
- enabled remote-control, forbidden effects, malformed known notifications,
  unknown lifecycle activity, order/correlation drift, response mismatch, and
  terminal mismatch remain closed protocol failures.

`turn/completed` is only a provisional terminal. The Adapter continues to
observe through owned process shutdown and seals success only when terminal
binding, response decoding, Observer state, and lower-client closure all remain
clean. A forbidden effect, protocol violation, or malformed lower-client event
after the provisional terminal discards the candidate response. The first
closed failure remains primary if shutdown later reports another failure.

Diagnostics expose only one of the frozen safe categories plus a bounded
Adapter-authored location and token. User content, assistant content, hidden
reasoning, account and rate-limit values, raw notification parameters, raw
exceptions, and authentication material do not enter the diagnostic callback,
Runtime, Store, Audit, Evidence, or Acceptance authority.

## Historical compatibility

The historical version-1 compiler, Adapter contract, configuration, and raw
Observer strategy remain unchanged and are reachable only for exact retained
version-1 Manifests. The current compiler:

- emits version 2 for every new operation;
- strictly validates either exact version 1 or exact version 2 retained
  authority;
- strictly reopens completed version-1 success and failure without
  reinterpretation;
- replays a completed version-1 failure without another assistant effect;
- closes interrupted version-1 Answer-only and Intent-analysis operations
  without recalling the assistant or silently recompiling them as version 2;
  and
- rejects stored version substitution during strict reopen.

The Runtime binds Proposal and Answer records to the exact Adapter identity in
their retained Manifest. No normalized event or Codex protocol type was added
to Domain or persistence schemas.
