## Review question

This review asks whether the pre-B1 Domain correction closes the retained
Frontstage Context Manifest and Intake Message Handoff contracts without
moving persistence, Assistant execution, routing, M2.5 Question/Answer, public
command, Goal, Workflow, Evidence, Acceptance, or CLI authority into P0.

It also checks whether the correction has one semantic owner for each
relationship, represents every required legal budget/omission state, rejects
mixed Handoff members, and leaves B1 through B5 able to consume the contracts
without adding a compatibility bypass or duplicating policy.

## Retained Context Manifest result

P0 adds one strict schema-version-1 `FrontstageContextManifest` record with an
owning codec, canonical projection, digest verification, exact budget limits,
and non-circular reservation relationship:

- the Manifest binds the preallocated Route Operation identity and reservation
  version without binding the not-yet-created Operation digest;
- the reserved Route Operation binds the final Manifest identity and digest;
- the Manifest repeats the exact current retained user Message content,
  Session policies, Focus presence, Assistant Profile and Adapter, response
  contract, compiler, budget, package identity, and selected or omitted source
  projections; and
- the Domain rejects stale Session/Message substitution, invalid Focus or
  Question relationships, oversized packages/selections, duplicate or
  overlapping selected/omitted sources, and more than 64 Manifest entries.

The current retained user Message relationship is factored into one private
Domain owner reused by Operation, Manifest, and clarification chains. P0 does
not create a second definition of currentness or let the later Store or
compiler reinterpret that relationship.

The omission matrix now represents the complete bounded input space. Focus is
either exact or absent; an active Intake Question is exact, absent, or omitted
for byte budget; prior Messages and Goal summaries may be omitted for their
selection or byte limits. In particular, Goal summaries may be omitted when
the canonical 65,536-byte package budget is exhausted. That reason remains
distinct from the 20-summary selection limit, and a source digest still cannot
be selected and omitted together.

## Discriminated Handoff result

`InteractionMessageHandoff` is now one closed discriminated union:

- `AUTHORIZED_INTAKE_ACTION` preserves the existing Pending Action,
  Resolution, Reservation, command, and exact one-message user-provenance
  meaning; and
- `INTAKE_CLARIFICATION` binds the exact current Session, retained user
  Message, Intake-Question Focus and Question digests, preallocated M2.5
  Command ID, canonical command-input digest, content bytes, and causality
  without carrying Pending Action authority.

The action member is the only Handoff accepted by `InteractionActionChain`.
Unknown discriminants, mixed-member fields, Question substitution, stale
current Messages, and clarification-as-action substitution fail at the owning
codec or relationship invariant. The clarification member is provenance for a
later existing M2.5 public command only; it does not create another Question,
Answer Binding, authorization, or command outcome.

## Findings and correction quality

The bounded reviews found four directly related contract gaps in the initial
P0 candidate: incomplete shared current-Message ownership, incomplete
selected/omitted and entry-budget constraints, a missing Assistant Adapter
identity in the Manifest, and adversarial tests whose earlier mismatches could
mask the intended substituted field. Those were corrected at their existing
owners rather than through caller conventions or duplicated Store checks.

A final review found that the omission matrix unnecessarily rejected
`GOAL_SUMMARY / BYTE_BUDGET` even though the accepted global package budget can
require that exact outcome. The restriction was removed and a positive codec
test was added while all overlap and size checks remained in place.

The result introduces no fallback, compatibility alias, generic framework,
optional-field bag, duplicated policy, or second authority. The later B1 Store
must persist and reopen this exact record; Slice 3 still owns the compiler and
Assistant Adapter. Those are planned consumers, not P0 follow-up work required
to make the Domain contract internally correct.
